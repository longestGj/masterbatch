# Masterbatch website renovation — local WordPress project

- This directory is the independent repository for the website renovation. Use this project's `planning/`, `docs/`, `.codex/agents/`, and `.agents/skills/`. Material in the sibling `D:/10MasterbatchDev` planning repository is background only unless the owner supplies or authorizes it for this site; its Gate instructions, manifests, and 15-agent workflow do not control this site's page lifecycle.
- Stage and commit only verified changes in this repository. Use a branch or PR when a change benefits from one; ordinary page work does not require either. Never stage or push the sibling planning repository as part of this site's work.
- The user will supply the existing site's materials. Do not independently reconstruct its content or treat public-site statements as approved claims. The known live URL is recorded only as a user-provided identity in `planning/SITE_BRIEF.md`.
- W1–W5 are project-scoped planning agents: facts, market/customer, positioning, site architecture, and first build slice. Each role's canonical instructions are in `.codex/agents/<agent_name>/agent.md`; the matching flat `.toml` is its Codex discovery adapter. Invoke only the role needed for the current question. They return evidence and proposals; the main task integrates approved decisions into the site's planning files. Their presence does not auto-run a five-stage chain.
- Gate 1 develops a candidate page direction from approved site planning and scoped evidence, choosing reuse, targeted gap research or full research according to the actual question. It may write only the assigned Page Spec and uses `.agents/skills/search-intent-evidence-analysis/SKILL.md` only for a material search-intent gap. Its role contract is `.codex/agents/gate1_page_direction/agent.md`.
- A separate, read-only Gate 1 Direction Review Agent checks the new direction and evidence before owner confirmation. Its role contract is `.codex/agents/gate1_direction_review/agent.md`. Neither Gate 1 role writes final copy, visuals or WordPress implementation.
- Gate 2 develops candidate page content in two passes: Skeleton, then Full Copy after the direction is confirmed. Its only write scope is the assigned Page Spec; it cannot approve copy, change site-wide ownership or direct WordPress implementation. Its role contract is `.codex/agents/gate2_page_content/agent.md`.
- A separate Gate 2 Buyer Review Agent reads each new Skeleton or Full Copy candidate before owner confirmation, returns findings to the parent, and never edits or approves the candidate. Its role contract is `.codex/agents/gate2_buyer_review/agent.md`.
- Gate 3 creates static page visual drafts from approved Gate 2 copy. Its only write scope is `planning/visuals/<PAGE_ID>/`; it does not inspect Staging, perform QA, or choose or modify WordPress implementation. Its role contract is `.codex/agents/gate3_page_presentation/agent.md`.

- Read `planning/SITE_BRIEF.md` for this site's facts and unknowns. For page work, use the single `planning/pages/<PAGE_ID>.md` referenced by `planning/SITE_MAP.csv`; SEO ownership lives in `planning/SEO_MAP.csv`. Follow `docs/WORKFLOW.md`.
